# Contributing

1. Pull `main` and create a feature branch: `git switch -c feature/exercises` (choose your module).
2. Keep changes scoped to your module. **Do not edit Room entity contracts or nav IDs** without asking the team.
3. Use readable commits such as `feat(exercises): add form validation`.
4. Sync, build and test locally; open a PR to `main`, and request at least one teammate's review.
5. Resolve conflicts with the owning developer, not by deleting the other person's changes.
6. Never commit `local.properties`, keys, `.idea/`, or build outputs.
